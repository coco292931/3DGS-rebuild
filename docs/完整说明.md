# 3D Gaussian Splatting 复刻项目 · 完整说明

本文档说明本项目的**运行环境、使用方法、底层原理、以及所依赖的全部技术**。

---

## 一、这个项目做了什么

从零实现 3D Gaussian Splatting（3DGS），把一组照片或一段环绕拍摄的视频，重建成可以在浏览器里
自由移动视角浏览的三维场景。

两条数据链路都已跑通：

| 链路 | 输入 | 输出 |
|---|---|---|
| 合成场景 | 程序生成的场景（位姿精确已知） | 用来验证实现正确性 |
| 真实场景 | 手机拍摄的环绕视频 | 真实物体的三维重建 |

**实测成绩**：

| 场景 | 测试集 PSNR | SSIM | 高斯数 |
|---|---|---|---|
| 合成场景（4 物体 + 棋盘地面，640×480） | **23.77 dB** | **0.929** | 24,075 |
| 真实场景（木桩，640×360） | **26.82 dB** | **0.904** | 约 40,000 |

（「瞎猜基线」——拿训练集平均图当预测——分别是 15.71 和 15.94 dB。）

## 三、如何使用

### 3.1 快速体验（用仓库里已有的成品）

```
双击 output/deliverable/view.bat        # 合成场景
双击 output/deliverable_real/view.bat   # 真实场景（木桩）
```

浏览器会自动打开。操作方式：

| 操作 | 效果 |
|---|---|
| 左键拖拽 | 旋转视角 |
| 滚轮 | 缩放 |
| WASD | 前后左右平移 |
| Q / E | 升降 |
| Shift | 加速 |
| URL 加 `?fade=0` | 关闭"贴近物体时的渐隐"（便于对比） |

### 3.2 从零跑通合成场景

```bash
# 1) 生成场景（GT 由独立的三角形软件渲染器产生，与高斯管线无关）
python tools/synth_scene.py --out data/synthetic --n-views 80 --width 640 --height 480

# 2) 训练（纯 PyTorch 后端）
python -m src.train --data data/synthetic --iters 2000 --downscale 1 --K 64 \
    --out output/mine --init-scale-factor 0.5
```

### 3.3 从零跑通真实视频

```bash
# 1) 抽帧。fps 必须够密——手持转半秒能转过二十几度，帧间视差过大直接匹配失败。
#    实测同一段视频：fps=2 抽 70 帧只注册 26 张；fps=6 抽 210 帧注册 202 张（96%）
ffmpeg -i video.mp4 -vf "fps=6,scale=1280:-1" -q:v 2 data/real/frames/frame_%04d.png

# 2) SfM 求相机位姿（pycolmap，自动用单相机模式）
python tools/run_sfm.py data/real --stage features
python tools/run_sfm.py data/real --stage match --sequential
python tools/run_sfm.py data/real --stage map

# 3) 训练（自动识别 COLMAP 数据，无需手动转换格式）
python -m src.train --data data/real --dataset colmap --backend cuda \
    --iters 30000 --downscale 2 --out output/mine-real --init-scale-factor 1.0 \
    --densify-until 15000 --opacity-reset-interval 3000
```

### 3.4 两个后端的区别与选择

```bash
--backend torch    # 本项目自写的纯 PyTorch 可微光栅化器（默认）
--backend cuda     # 官方 diff-gaussian-rasterization（需先编译）
```

| | torch 后端 | cuda 后端 |
|---|---|---|
| 依赖 | 只要 PyTorch | 需要编译 CUDA 扩展 |
| 速度 | 5 iter/s | **89 iter/s** |
| 质量上限 | 22.5 dB（K 截断导致训练后期崩溃） | **26.8 dB，且持续上升** |
| 用途 | 理解算法、正确性对照 | 实际出结果 |

**编译官方扩展**（仅在需要 cuda 后端时）：


## 四、底层原理

### 4.1 场景表示

3DGS 不用神经网络、不用体素、不用网格，而是用**几十万个各向异性的三维高斯**来表示场景。

每个高斯有 59 个可学参数：

| 参数 | 维度 | 含义 |
|---|---|---|
| 位置 μ | 3 | 高斯中心 |
| 旋转 q | 4 | 四元数，决定椭球的朝向 |
| 缩放 s | 3 | 三个轴的长度（存 log，用时 exp） |
| 不透明度 α | 1 | 存 logit，用时 sigmoid |
| 球谐颜色 SH | 48 | 3 阶球谐 × 3 通道，提供**视角相关**的颜色 |

**球谐颜色是精髓**：同一个点从不同方向看颜色不同，所以镜面反光和金属质感能被表达出来。
这是 3DGS 比传统点云强的地方。

### 4.2 渲染（前向）

**第一步：形状投影**。三维协方差矩阵是 `Σ = R S Sᵀ Rᵀ`。投影到屏幕时不能直接投 Σ，
要过投影函数的雅可比 J：

```
Σ₂D = J W Σ Wᵀ Jᵀ
```

其中 W 是相机旋转。得到 2D 协方差后求逆就是 conic（椭圆参数）。

这里有个官方细节：**给 Σ₂D 的对角线加常数 0.3**，相当于低通滤波，
不然高斯缩到亚像素时画面会闪烁。

**第二步：求 alpha**。像素中心到高斯中心的偏移 d，

```
α = opacity · exp(−½ dᵀ · conic · d)
```

**第三步：排序与合成**。从近到远做前向 alpha 合成：

```
T_i = Π(1 − α_j)    (j < i)
C   = Σ T_i · α_i · c_i + T_末 · 背景色
```

排序必须严格按深度，否则半透明混合的结果是错的。

### 4.3 训练

**损失函数**：L1 与 D-SSIM 加权（λ=0.2）。纯 L1 会糊，纯 SSIM 会出伪影。

**自适应密度控制**——这是 3DGS 区别于 NeRF 的关键机制：

- 每 N 步统计位置梯度，**梯度大**说明该区域表达不足
- 尺度小 + 梯度大 → **clone**（复制一份，往梯度方向挪）
- 尺度大 + 梯度大 → **split**（一分为二，尺寸缩小）
- 定期**剪枝**不透明度过低的高斯
- 每 3000 步做一次 **opacity reset**，把不透明度压回去，
  逼着"又大又透明"的垃圾高斯重新竞争

**球谐升阶**：训练前期只用 DC 分量（相当于固定颜色），每隔一段升一阶，
逐步放开视角相关的颜色。这样更稳。

### 4.4 两种光栅化实现的差别

| | 官方 CUDA | 本项目纯 PyTorch |
|---|---|---|
| 策略 | 16×16 tile 分块，块内排序，**无上限** | 按像素分桶，每像素保留最近 K 个 |
| 反向 | 手写 CUDA 反向核 | autograd 自动求导 |
| 显存 | 按 tile 局部展开，很低 | 稠密 [像素数 × K] 张量，随 K 线性增长 |

**K 截断是纯 PyTorch 路线的死穴**：被截断的高斯拿不到梯度，优化器转而把没被截断的
高斯撑得更大去补窟窿，片元数继续涨，形成正反馈。实测 K=20 时峰值 21.95 dB 后崩，
K=32 是 22.37 后崩，K=64 才勉强到 23.49 但最终仍会崩。**这是架构问题，调参解决不了。**

### 4.5 真实场景的前处理

**SfM（从图像恢复相机位姿）**：

```
SIFT 特征提取 → 顺序匹配 → 增量式重建（pycolmap）
```

**点云三重过滤**（本项目的经验，缺一不可）：

| 条件 | 实测剔除数（30741 个点） |
|---|---|
| 重投影误差 > 1.5 px | 807 |
| 空间离群（5 近邻平均距离 > p97） | 1549 |
| 距相机簇中心 > 3× 相机半径 | 兜底 |

**空间离群最致命**：KNN 距离的 p99 是 p50 的 **19 倍**，这些稀疏点变成高斯后
会甩到远处，把屏幕覆盖面积撑爆。

**上方向对齐（必做）**：SfM 的世界坐标系由前两帧决定，**和"z 朝上"没有任何约定关系**。
实测两段不同视频，"图像下方"平均都指向世界 +z——**场景是倒的**。本项目用
"相机图像上方的平均方向"定 up 并自动旋转对齐（人不会倒着拿手机，这个信号比
点云主平面法线可靠，后者会被离群点带偏）。

### 5.3 验证手段

**这是本项目的重点，不是附属品。**

| 手段 | 说明 |
|---|---|
| 与朴素实现逐像素对比 | `rasterizer.py` 里有逐高斯循环的参考实现，向量化版必须复现它（偏差 < 1e-5） |
| 有限差分梯度校验 | 双精度下解析梯度与数值梯度相对误差 1e-8（**必须 float64**，float32 下差分方法自身会失效） |

| 查看器真实交互验证 | selenium 走浏览器真实输入管线，拖拽 150px 后 yaw 恰好变化 0.900，与代码公式逐位对上 |

## 六、已知限制

1. **纯 PyTorch 后端的天花板**：K 截断导致训练后期崩溃，无法通过调参解决。
   要出质量必须用 CUDA 后端。
2. **速度**：torch 后端比官方 CUDA 慢两个数量级（391 ms vs 1.5 ms 单帧）。
3. **优化器动量**：每次密度控制后重建 Adam，动量会丢失（官方实现会搬运 optimizer state）。
4. **查看器只用了球谐 DC 分量**，颜色不随视角变化。
5. **真实场景的漂浮高斯**：桌面之外的背景杂物重建得较碎，是视角覆盖不均 + 训练步数的双重结果。
6. **素材依赖强**：主体占画面比例小、表面光滑、光照突变、纯旋转拍摄这四种情况都容易失败。
   详见 README 的拍摄建议。
7. **评估口径偏窄**：只看平均 PSNR 会掩盖视角方差（某场景三个测试视角分别是
   22.80 / 28.02 / **12.04** dB，平均值完全不能反映"三分之一是废的"）。
